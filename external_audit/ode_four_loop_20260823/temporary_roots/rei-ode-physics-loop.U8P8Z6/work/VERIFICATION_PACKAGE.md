# PHASE 7 MINIMAL DECISIVE VERIFICATION PACKAGE

The packages below are designs only. They do not authorize repository writes or production execution in this loop. Every claimed pass must be bound to exact source/runtime/input identity and raw artifacts.

## V-H001 — Falsify the active-face verified hybrid solver

### 1. Testable claim

A separately implemented H-001 reference kernel can simultaneously preserve the declared H/He closed-simplex physics, correct absorber normalization, rigorously enclose each algebraic solve, control independently evaluated smooth-branch defect/physical QoIs, and preserve event topology/restart custody without relying on floors, tautological ledgers, or same-code parity.

### 2. Required inputs

- Frozen equations, units, abundance/cross-section conventions, four group definitions, all branch/table predicates, H/He/charge content vectors, vacuum/trace rules, event functions, simultaneous-event priority, restart maps, and independent physical QoIs/budgets.
- Exact analytic fixtures: pure H, pure He I, pure He II, mixed opacity, zero-opacity/emissivity, zero-rate, equilibrium/linear transfer, exact invariant face, face activation/deactivation, trace sequence, and declared vacuum.
- Exact numerical adversaries: signed sum `[1e20,1,-1e20]`; both 2×2 Krawczyk witnesses; subnormal/overflow/transcendental-bound boxes; nearly singular base/Schur systems.
- Hybrid fixtures with analytic/enclosed truth: two crossings in one step, tangency/double root, repeated root after restart, simultaneous events, roots bracketing a table knot, and zero-time event iteration.
- An independently coded primitive-flux/stoichiometric/thermal-reservoir oracle and a high-precision or validated trajectory/reference implementation that shares no candidate solver path.
- Smooth-branch refinement sequence with at least four successive step halvings and exact/validated QoIs; exact qualified deployment runtime.

### 3. Expected result if H-001 is correct

- Pure-He II opacity per H has one `YHE` factor; all pure-absorber shares are exactly/verifiedly `(1,0,0)` in the declared ordering; mixed shares are nonnegative and sum to one when total opacity is positive; zero-opacity takes the explicit zero-absorption branch.
- Exact invariant faces remain exact with no floor; activation/deactivation is unique, inventory-preserving, non-chattering, and shows the proved smooth/transition order.
- Exact sums/solutions lie inside every claimed enclosure; an inconclusive certificate is typed as inconclusive.
- Independent photon/energy mutation checks reject omissions; clean primitive ledgers close within their pre-registered dimensional budgets.
- Smooth defects/QoI errors decrease with the predicted order and remain inside owner budgets; full/two-half distance is only corroborative.
- All simple roots are isolated; tangency/repeated cases are either enclosed by the explicit strategy or typed as unresolved, never silently passed. Rollback/rebuild/restart preserves all inventories/reservoirs and authorized event order.
- Low-rank and dense residual/Jacobian/solve results are enclosed-equivalent; ill-conditioned cases select the dense verified fallback.

### 4. Expected result under the strongest competitor

Under H-005/minimal patch or a generic solver switch, the pure-He II formula may improve, but at least the signed-sum/Krawczyk, exact-zero, independent-ledger, all-root/restart, or global-QoI tests still false-pass or remain absent. Under H-003/H-004, boundary/regime cases may improve but whole-branch verified algebraic/event/QoI coverage remains incomplete unless they effectively supply H-001's missing contracts.

### 5. Pass criterion

Pass only if all of the following hold under exact identity:

1. every analytic/limiting fixture satisfies exact dimensional, abundance, share, inventory, sign, and branch expectations;
2. every exact rational/high-precision target is contained by the claimed enclosure, with zero false-success statuses;
3. every clean primitive ledger meets pre-registered physical budgets and every common-mode mutation is rejected;
4. for three consecutive smooth-branch halvings after the predeclared asymptotic-entry rule, verified error-ratio intervals contain the theorem-predicted ratio 4 and exclude first-order ratio 2, while every named QoI remains within its owner budget;
5. every hybrid fixture is found/ordered or explicitly unresolved before admission, analytic root/event time is enclosed, and restart conservation holds exactly or by outward interval containing zero residual;
6. dense/low-rank equivalence is verified on every fixed branch, and all conditioning thresholds trigger the declared fallback;
7. no floor, candidate-derived expected value, same-code ledger, or compatibility artifact participates in admission.

Absence of frozen physical budgets/conventions makes the result ambiguous, never pass.

### 6. Kill criterion

One false enclosure; one missed/incorrectly ordered topology-changing event admitted as success; one nonunique/chattering face transition; one H/He inventory violation; one primitive physical mutation not detected; one independently over-budget QoI; or one branch without the required valid decomposition/fallback kills H-001 as stated.

### 7. Ambiguity condition

- Certificate returns typed inconclusive before state consumption.
- Reference independence is disputed, exact event multiplicity is unknown, refinement is not in its asymptotic regime, true-path enclosure is too wide, or owner budgets/conventions are absent.
- Performance failure alone is ambiguous for correctness if verified dense fallback passes; it kills only the acceleration subclaim.

### 8. Cheapest next action

Before solver implementation, write a standalone specification/test-vector packet containing the units/content matrices, pure-absorber formulas, the two Krawczyk witnesses, exact face rules, primitive-ledger equations, and six hybrid event polynomials. Have a physics owner and an independent numerical reviewer sign the conventions. This cheaply kills inconsistent normalization, face, event, and budget assumptions.

### 9. Escalation path

Specification oracle packet → scalar/one-site reference kernel → four-site fixed smooth branch with dense verified solve → branch-correct reconstruction/defect and QoIs → isolated event/restart suite → block-plus-low-rank optional acceleration → bounded non-production segment → only then consider a new corrected-science stage. Any earlier fatal result returns to evidence/hypothesis/validation as typed by the gate.

## V-H002 — Falsify dual-lane independent admission and custody

### 1. Testable claim

A typed two-lane architecture can prevent historical compatibility, correlated references, runtime/provenance drift, controller false-success, containment failures, and resource-exhausted partial outputs from being consumed as corrected science, while an independently derived physical reference detects known solver defects.

### 2. Required inputs

- Frozen artifact types/interfaces and allowed-consumer matrix for `FORENSIC_COMPATIBILITY_ONLY`, `CODE_VERIFICATION`, `NUMERICAL_VALIDATION`, `EMPIRICAL_PHYSICAL_VALIDATION`, and `SCIENTIFIC_PROMOTION`.
- Independence graph covering equations, constants, tables, preprocessing, libraries, generators, authors/reviewers, and expected-value provenance.
- Exact source/tree/dirty-state, interpreter/packages, dynamic libraries/BLAS/libm, CPU/math settings, tools/PATH, inputs/tables/config, validator, output, generation, and parent identities.
- Complete transition table for start/success/failure/event/pause/crash/resume/restart/new-generation and atomic/quarantine rules.
- Clean golden fixtures plus mutations for the extra `YHE`, complement share, tautological ledgers, removed event/restart, false certificate, nonfinite/overflow, and reference shared-module injection.
- Identity, status, custody, package, and resource attacks listed in the Phase-5 review.

### 3. Expected result if H-002 is correct

- Every clean fixture reaches only its authorized tier; a forensic artifact is structurally non-coercible to corrected science.
- Blind independent reference cases detect every known physics/numerics mutation without reading candidate output.
- Any identity, terminal-state, event-custody, partial-write, containment, tool, generation, or quota failure blocks consumption and quarantines all partial products.
- Historical artifacts remain immutable; corrected artifacts receive new lineage and cannot redefine comparison baselines.
- Claim tiers remain explicit through packaging and every downstream consumer.

### 4. Expected result under the strongest competitor

Under one-lane hash receipts or same-code parity, renamed/replayed/partially written artifacts, shared-module references, terminal resumes, or runtime/tool drift can retain a green label; known physical mutations can evade correlated comparisons. Passive receipts may exist but an unchecked consumer still accepts the result.

### 5. Pass criterion

- `100%` of the finite pre-registered clean matrix reaches exactly its authorized tier.
- `100%` of the finite pre-registered mutation/identity/transition/custody/resource/lane-confusion matrix fails before scientific consumption and leaves no admissible partial artifact.
- Every transition is atomic, every terminal state is absorbing, every quota is enforced during execution/packaging rather than after buffering, and every downstream consumer enforces the lane type.
- The blind physical reference independently detects all seeded known defects.
- Independence graph shows no candidate-output-derived expected value and no unacknowledged shared solver/ledger algebra.
- Raw identities, decisions, quarantine outcomes, and resource maxima are preserved.

### 6. Kill criterion

One forensic-to-science coercion; one failed/partial/quota-killed artifact consumed as success; one unbound identity that can alter numerical meaning; one known physics defect missed because of shared candidate algebra; one corrected overwrite/redefinition of historical lineage; or one downstream consumer that ignores the typed gate kills H-002.

### 7. Ambiguity condition

- A shared conceptual root cannot yet be independently derived but is fully disclosed.
- A host capability prevents a named adversarial test, or exact dynamic-library/math identity cannot be observed.
- The architecture blocks consumption but independent physical-validation data do not exist. This can pass custody while remaining ambiguous for physical validity; dimensions must not be collapsed.

### 8. Cheapest next action

Draft the artifact type/consumer matrix, independence graph, and finite transition/mutation matrix without changing production code. Walk the known extra-`YHE`, false-certificate, forensic-lane, terminal-resume, pipe-flood, and symlink/package cases through it on paper; any path to corrected-science consumption kills the design before implementation.

### 9. Escalation path

Paper/type-state model → hermetic toy gate with deliberate mutants → independent oracle implementation/blind fixtures → isolated non-production controller/custody harness → exact-runtime bounded segment → external verification/validation review → only then integrate a new corrected-science lane. Physical validation remains a separate later authority.
