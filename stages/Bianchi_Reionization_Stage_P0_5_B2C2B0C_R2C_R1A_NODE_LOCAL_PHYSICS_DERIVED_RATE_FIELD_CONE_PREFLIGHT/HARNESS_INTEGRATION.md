# Research-harness integration

Only `physmath-research-harness-gpt56(6).zip` was applied in this stage.
`physmath-coding-harness-gpt56(5).zip` was deliberately not invoked.

The executed research loop was:

1. freeze the primary question, scope, forbidden repairs, and three competing
   hypotheses;
2. build an evidence ledger from primary radiative-transfer literature and
   canonical repository definitions;
3. audit claim provenance and distinguish theorem, numerical evidence,
   inference, and non-authorizing diagnostic;
4. derive the corrected state/flux/budget equations with dimensions, signs,
   limits, and conservation laws;
5. stream every inherited node and group row, then reduce independently to the
   locked macro/global moments;
6. attack the promoted hypothesis with endpoint, cap, timestep-refinement,
   hidden-reservoir, thermal, and identifiability objections;
7. preserve failed attempts and negative results;
8. decide `REJECT/HOLD/PROMOTE` and close the stage with a narrow authorization.

No production solver feature, performance optimization, API redesign, or
coding-harness implementation task was started.
